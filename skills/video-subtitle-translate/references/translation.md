# 当前助手的字幕翻译约定

识别工具只提取文字，翻译由执行技能的当前助手完成。不默认调用 Ollama、千问或另一个本地大语言模型。不把自动识别原文直接标记为已汉化。

## 翻译数据

使用稳定 ID 对照，批次翻译保存结构化结果。辅助脚本接受如下格式，时间单位为原视频绝对秒：

```json
{
  "cues": [
    {"id": "c001", "start": 12.3, "end": 15.1, "text": "Good morning.", "zh": "早上好。"},
    {"id": "c002", "start": 16.0, "end": 18.5, "text": "We meet again.", "zh": "我们又见面了。"}
  ]
}
```

`text` 保留提取原文，`zh` 放译文。原文清单也使用 cues 数组，可无 zh。对无法辨清或按任务排除的条目，显式设置 `zh: ""` 并写非空 `skip_reason`，不要直接从清单中删掉。脚本校对的是 ID 与时间轴，不会判断译文质量。

## 分批实施

1. 先读本批原文及适量前后文，保存术语表中的人名、称谓、专有名词与已有译法。批次大小按上下文容量调整，不固定强塞整部视频。
2. 校正有证据的 OCR/ASR 错词。无法辨清时局部看图或听音，分开记录原提取结果、修正和不确定性，不能为了“通顺”补造内容。
3. 中文自然、含义忠实、称谓统一；保留说话语气，避免逐词硬译。只翻译用户要求的对白、旁白、气泡或歌词，不增加情节、解释或审核评论到字幕中。
4. 每个 ID 都给出译文或明确排除原因；不改起止时间。需要重新切句时另存 layout 对照，不能通过改时间来掩盖漏译。
5. 字幕尽量简洁并与显示时长匹配，优先在语义/标点处换行，最多两行；过长句需要缩写或按语音/画面变化合理拆分，不能机械等分时间。
6. 保存该批结果、完成的 ID 和术语后再继续。检查缺失/多余/重复 ID，特别留意同词连续误识别、跨块时间重叠和机器生成的“感谢观看”等幻觉；这些内容如确实存在则保留，不用黑名单一律删除。

## 复核边界

对提取存疑、长句、多人同时说话、切换很快及剧情转折处重点复核。没有新问题时不反复重跑整片识别/检查。适用的内容限制仍按当前平台要求处理，不从过去的任务继承用户声明、角色判断或授权。不能处理的条目保留原件并简要记录。
